# 交付物「呈现」调研报告（v1）

> 调研日期：2026-09-16 ｜ 项目：TTS 回流语料「准入验证 + 维度画像 + 报告」工具集
> 问题：**最终 xlsx 交付物只有统计数字、没有呈现（0 图表、0 图片）**，与上游《语料合理性验证维度框架》要求的「每维度一张分布图 + 偏差告警」存在 gap。
> 方法：盘点现状产物（本地实测）＋ 网络调研（coqui/corpusgen/Riva/cv-tbox/ydata-profiling 等）＋ 本机库能力实测。
> 标记：**✓已核实**（一手源码/文档/本机实测）｜**⚠受限/有争议**｜**不支持**｜**?待核**。

## 0. 结论速览

1. **现状确认（本地实测）**：三个 run 目录的 `数据集_全字段.xlsx` 全部 **charts=0 / images=0**；「维度分布」sheet 是把 6 个维度的聚合数字用「标题/项/值」三列**堆在一个 sheet** 里，不是按维度分 sheet，更没有任何图。✓
2. **需求文档其实早就要求了图**：《语料合理性验证维度框架》对 14 个子项逐个定义了产出 sheet，其中明确写「四组**直方图**数据」「与目标配比差距 + 偏差**告警**」「音素**组合**（bigram/trigram）表」「**缺失组合**」等——**现状只落地了约 4 个数字 sheet**。✓
3. **业界做法高度一致，且不追求图表数量**：Coqui、NVIDIA Riva、corpusgen 三家都是「**每维度 1–2 张诊断图 + 一张数字差异表**」。Riva 的官方音素教程整个 notebook 只画 **1 张对比条形图**（Bokeh）+ 1 张差异表。✓
4. **技术选型明确：不要换库**。`openpyxl` 足以覆盖「条形/堆叠/折线/饼/环/散点 + `gapWidth=0` 模拟直方图」这一层，**零新增依赖**；且本项目是「写 + 读回/合并」流程，而 **XlsxWriter 官方明确「不能读取或修改已有 xlsx」** → 换 XlsxWriter 会打断现有链路。✓
5. **openpyxl 实测能做与不能做**（本地实测）：直方图可模拟（写入 XML 确认 `gapWidth val="0"`）；箱线图/热力图/ECDF/漏斗**无原生** → 走 matplotlib PNG 嵌入或「先算后画」。**但 matplotlib 在本项目 `.venv` 里没装**（实测 MISS）→ Phase 2 需新增依赖。✓
6. **多语种是选型的硬约束**：若目标语含**乌尔都语（RTL）**，ECharts 至今无 RTL 布局镜像（issue #19609 自 2024-02 仍 Open）；主要矛盾是**字体**（默认 DejaVu 对中文/天城文/孟加拉文必出豆腐块，实测），布局 RTL 镜像需手工处理。✓

**问题**：全是「点估计」数字，**没有分布形状、没有分位可视化、没有与目标区间的对比、没有告警色**。读者无法直观判断「这批语料长什么样、哪里不达标」。

## 2. 调研发现

### 2.1 现状为何如此：`report.py` 的设计只做了「落表」

`corpus_kit/report.py` 的 `build_report()` 只做三件事：写 Sheet1 明细、Sheet2 行级汇总、Sheet3 六段「项/值」堆叠、Sheet4 字段说明。**没有任何 `openpyxl.chart` 调用**。中间态 `dims/*.json` 里其实**已经存了做图所需的数据**（如 `phoneme.single` 全量字典、`vocab.top` 列表、`length.char` 分位数、`bi` 双音素字典），只是没有被「画」出来。

### 2.2 业界范式：三家工具的做法

| 工具 | 图表 | 技术栈 | 输出 | 许可 |
|---|---|---|---|---|
| **Coqui `dataset_analysis`** ✓ | `AnalyzeDataset`：4 张散点 + 1 张词频条形；`PhonemeCoverage`：**一张超宽横向条形**（每柱标 count 与 %），另打印「最稀有 5 音素」 | matplotlib + pandas + scipy | 仅 notebook 内联 | MPL-2.0（46k★） |
| **NVIDIA Riva `tts-phoneme-distribution`** ✓ | **3 张 Bokeh 纵向条形**；核心第 3 张是「实际(purple) vs 参考(white)」双 series 叠图（参考先按 `scale=actual_total/ref_total` 缩放）；配 `PrettyTable` 差异表（`(1-min/max)*100`） | **Bokeh** + cmudict + prettytable | notebook + 示例 PNG | 教程集（Apache-2.0 常态） |
| **corpusgen** ✓ | **本身不画图**，但提供 `CoverageTrajectory.coverages/gains`，docstring 原话 *"the classic coverage saturation curve used in every corpus selection paper"* | 纯 Python | 文本报告 + JSON | Apache-2.0（**仅 1★**） |
| **cv-tbox-dataset-analyzer** ✓ | bar/area/line/freq 四类图 + 交叉表；支持**对数轴**、`ReferenceLine`、一键下载 PNG | React + **Recharts** | WebApp | ?待核 | 
| **ydata-profiling** ✓ | **报告信息设计最佳参考**：Overview / **Alerts**（自动列质量问题）/ Reproduction 三段式 | pandas + HTML | 自包含 HTML | BSD-3 |
| **ESPnet / NeMo** ⚠ | **未发现**专门的语料分布报告模块；ESPnet `collect_stats` 是特征归一化统计 | — | — | Apache-2.0 |
| **Great Expectations Data Docs** ✓ | 每条校验 = `success` 布尔 + 期望定义 + 观测值 → HTML | — | HTML | Apache-2.0 |

**三家共识**：① 每维度只用 **1–2 张图**；② **必配一张数字差异表**；③ 覆盖率类用**曲线**、构成类用**条形/堆叠**、频次长尾用**横向条形**、分布形状用**直方图**；④ **告警靠颜色/阈值标记，不靠图形本身**。

### 2.3 维度 → 推荐图表类型 → 可抄的实现

> 关键洞察：openpyxl 的限制不是「画不了曲线」，而是「**不会替你算聚合**」。任何先在 Python 里算好的 x/y 序列都能用 `LineChart/ScatterChart` 画；它缺的是**原生分箱**与**统计图形**。对策：**聚合在 pandas/numpy 完成，Excel 只负责画**。✓（本机实测）

| 维度 | 主图 | 辅助图 | 可抄参考 | openpyxl |
|---|---|---|---|---|
| 字符集审计 | 横向条形（长尾可对数） | 频次表 + 白名单外单列 | Coqui `PhonemeCoverage`（barh + 标注 count/%） | ✓ `type="bar"` |
| **长度分布** | **直方图** | 箱线图（离群）+ **ECDF**（叠 20/300 门控线） | Coqui `AnalyzeDataset`；Coqui wiki 要求「Gaussian-like 分布」 | 直方图 ✓（`gapWidth=0`）；箱线图 **✗→PNG** |
| **句式配比** | **分组条形：实际 vs 目标** | 偏差% 用 error_bar；或 100% 堆叠 | **Riva 双 series 叠图 + 差异表** | ✓ 双 series；**无 ReferenceLine → 目标做第二条 series** |
| 词频分布 | **Zipf log-log（rank×freq）** | **Lorenz 曲线 + Gini**；Top-N barh | corpusgen 的 entropy/JSD/CV/PCD 指标口径 | ✓ ScatterChart（先取 log）；**Gini 需自己算** |
| 音素分布 | 横向条形（降序+标%） | 与参考分布双 series | Coqui `PhonemeCoverage` + Riva 对比条 | ✓ |
| **音素组合/双音素** | **覆盖率饱和曲线**（x=已选句数, y=累计覆盖%） | 双音素矩阵**热力图** | **corpusgen `trajectory.py`**；SpeechWeave Fig.7 | 曲线 ✓ LineChart；**热力图 ✗→PNG/单元格底色** |
| 缺失组合 | 缺失项 barh | 清单表 + 越界标红 | corpusgen `missing_phonemes` + `MAX_MISSING_DISPLAY=50` | ✓ + `PatternFill` |
| 门控通过率 | **漏斗图** | 通过/淘汰 100% 堆叠 | Riva/Coqui「门控前后计数 + 清单」 | **漏斗 ✗→barh 倒序模拟** |
| 词源/外来词 | **堆叠条形** | 饼/环看构成 | cv-tbox 堆叠；ydata-profiling 结构 | ✓ `grouping="stacked"/"percentStacked"` |
| NSW 分布 | 横向条形 + 分类占比 | 句级明细下钻 | corpusgen `SentenceDetail` 双层结构 | ✓ + 明细 sheet |
| 情感/内容形态 | 100% 堆叠条 / 环图 | 交叉表 | cv-tbox `crossTabTable` | ✓；交叉表热力图 ✗→PNG |

### 2.4 交付形态选型对比

| 形态 | 图种 | 交互 | 非技术人可读 | 可复现 | 跨平台 | 体积 | 关键坑 |
|---|---|---|---|---|---|---|---|
| **xlsx + openpyxl 原生图** | 条形/堆叠/折线/饼/环/散点/雷达/面积；**无**箱线/直方/热力/漏斗 | 弱（可冻结/筛选） | **高** | **高** | **最好** | **+6–13 KB/图**（实测 7 KB）✓ | 各 Office 渲染有差异 ⚠ |
| **xlsx + matplotlib PNG 嵌入** | **全图种** | 无 | 高 | 高 | 最好 | 单图数十~数百 KB ⚠ | **需字体治理**；本项目 venv **未装 matplotlib** ✓ |
| **自包含 HTML（ECharts）** | 30+；无原生箱线/ECDF | **强** | 高 | 高 | 好 | **echarts.min ~1.03 MB**（simple 470 KB）✓ | **无 RTL 布局** |
| **自包含 HTML（plotly）** | 最全（含 funnel/treemap/box/violin） | **最强** | 高 | 中 | 好 | **~4.6 MB 基线** ✓ | 静态导出需 kaleido+Chrome |
| PDF | 全（依赖生成链） | 无 | **最高** | 高 | 好 | 中 | 无下钻 |
| notebook | 全 | 中 | **低** | **最高** | 中 | 小（环境大） | 不适合发给业务方 |
| PNG 组图 | 全 | 无 | 中高 | 高 | **最好** | 每图数十~数百 KB | 脱离数字，需配表 |

**选型结论**：**xlsx 原生图表（主交付，零新依赖）→ 统计图形补 matplotlib PNG → 再补自包含 HTML（业务方友好）**。不用换 XlsxWriter（**它不能改已有 xlsx**，官方原文）✓。

### 2.5 openpyxl 能做 / 不能做（本地实测）

| 图种 | 原生 | 替代 |
|---|---|---|
| 直方图 | 无类，但 **`BarChart(type="col", gapWidth=0)` 可模拟**（实测 XML 生成 `gapWidth val="0"`）✓ | 分箱在 Python 先算 |
| 箱线图 |  | `StockChart` 模拟 ⚠ / error_bar / **matplotlib PNG** ✓ |
| ECDF/CDF | ✗ | 先算 x,y → LineChart ✓ |
| Zipf / Lorenz | ✗ | 先取 log / 累计 → Scatter/Line ✓ |
| 覆盖率饱和曲线 | ✗ | LineChart ✓ |
| 热力图 | ✗ | PNG 嵌入 / `PatternFill` 单元格底色 ✓ |
| 漏斗 | ✗ | barh 倒序模拟 ✓ |
| 饼/环/堆叠/分组条 | ✓ | 直接用 |
| 嵌入 PNG | ✓ `openpyxl.drawing.image.Image`（实测同簿可共存 chart1.xml + image1.png）✓ | 非 png/jpeg/gif 需 PIL |

**新增依赖提示**：本项目 `.venv` 实测 **matplotlib / PIL / xlsxwriter / plotly / altair 均未安装**（只有 pandas 3.0.5 + numpy 2.5.3 + openpyxl 3.1.5）。所以「零依赖」只对 **openpyxl 原生图**成立；Phase 2 起需装 matplotlib（+PIL）。

### 2.6 非拉丁文字的渲染坑（多语种硬约束）

| 事实 | 证据 |
|---|---|
| **默认字体必出豆腐块** | matplotlib 默认 DejaVu 对中文/天城文报 `Glyph missing`；实测换 `Noto Sans SC`/`Nirmala UI` 才正常 ✓ |
| **matplotlib 能整形（但非文档承诺）** | 二进制内含 raqm/harfbuzz；阿拉伯语实测正确连写+RTL ✓；官方 docs **未记录** RTL/bidi 能力 ⚠ → 需运行时探测 |
| **matplotlib 不做段落级 bidi 镜像** | 需手工 `invert_xaxis()`、y 轴置右、刻度右对齐 ⚠ |
| **ECharts 无 RTL 布局** | issue #19609 自 2024-02 至今 Open；5.5.0 只加了阿拉伯语翻译字符串，未加 RTL 镜像 ✓ |
| **浏览器擅长文字整形** | HTML 外壳 + 浏览器渲染标签文字最稳；但无头渲染（kaleido）可能缺字体 ⚠ |

**一句话**：**字体是主要矛盾，方向是次要矛盾**。把 Noto 系字体随交付物打包，xlsx 内嵌 PNG 与 HTML 都能正确显示乌尔都语/孟加拉语；仅「图表布局的 RTL 镜像」需手工处理。

## 3. 建议的落地路线（分阶段）

> 原则：**先零依赖补图 → 再补统计图形 → 再上 HTML → 最后治理多语字体**；每阶段都保持「xlsx 仍是可交付产物」。

**Phase 1（最高优先，半天~1 天，零新依赖）**
- `report.py` 从「4 个 sheet」扩为「按维度分 sheet + 概览 sheet」，呼应需求文档的 14 子项；
- 每 sheet 挂 1–2 张 openpyxl 原生图：长度 `BarChart(gapWidth=0)`、句式「实际 vs 目标」双 series、词频 Top-N、门控漏斗（barh 倒序）、字符集 barh、词源/NSW 堆叠；
- 新增**概览 sheet**：总体通过/告警计数 + 每维度一行红黄绿；
- 告警复用现有 `_tag()` + `PatternFill`，阈值取需求文档锁定值（字符 20–300、录音句 5–30 词、核心单元 ≥5 次、高频组合 ≥3 次）。

**Phase 2（1–2 天，需装 matplotlib）**
- matplotlib Agg 预渲染并嵌入：箱线图、ECDF（叠门控线）、Lorenz+Gini、双音素热力图、覆盖率饱和曲线；
- 同时导出独立 PNG 组图目录（贴 PPT/微信用）。

**Phase 3（2–3 天）**
- 自包含 HTML 报告（首选 pyecharts/ECharts，体积优）；结构照抄 ydata-profiling：Overview → 逐维度（图+差异表）→ 明细。

**Phase 4（1–2 天，多语扩展必经）**
- 打包 Noto 字体（SC/Arabic/Bengali/Nastaliq Urdu）；matplotlib `addfont`；HTML `@font-face`；
- **字形探测门控**（缺字形则报警，不静默出 tofu）；
- RTL 布局手工镜像。

**Phase 5（可选）**：PDF 正式版（weasyprint，纯 Python，无浏览器）。
