## 1. 目标与交付物

### 1.1 目标
对 TTS 回流语料做 **准入（gate）→ 维度画像（profile）→ 报告**，输出「分布合理的数据集」候选 + 全套验证指标。本轮以斯瓦西里语（sw-KE）回流数据为对象，架构预留多语种。

### 1.2 交付物（每次运行产出，进 output/）
1. 数据集_全字段.xlsx：**保留回流表头字段**，追加维度列（gate 状态、长度、句式、NSW 标记、词源、音素计数等），句子级一行一条
2. 维度分布_*.xlsx（或单 Excel 多 sheet）：合法性 / 长度 / 句式 / 词汇 / 音素 / 词源 各分布表
3. 字段说明.xlsx：原表头字段说明 + 新增字段说明（子表）
4. manifest.json：输入文件哈希、参数、版本、seed、时间戳 → **可复现**
5. 中间态 
ecords.jsonl / sentences.jsonl：断点续跑 + 审计

## 2. 输入契约（本次设计的关键修正）

### 2.1 分层
`
上游回流数据（xlsx / csv / json / txt —— 格式不可预期，且可能是行边界丢失的整段 dump）
   │ ① 接入环节（ingest）
   │    ├── ingest_xlsx.py        表格 → txt（原表字段透传）
   │    ── prepare_input.py      任意格式 → 清洗 → txt（2026-09-17 新增，见 §14）
   ▼
INPUT.txt（工具集唯一入口：一行一条记录）
   ＋ INPUT.meta.json（原表头字段说明、文本列名、来源信息）
   │ ② 准入 gate（工具集内）
   ▼
验证 / 画像 / 报告
`

- **工具集只认 txt**（UTF-8，一行一条；需要保留原字段时用 \t 追加列，meta.json 声明列顺序）。csv/json/xlsx → txt 的转换由**上游或 agent 完成**，不属于验证工具集（文档已拍板：靠需求方自己转换）。
- 现有 opneayxl 读取逻辑**迁出工具集**，做成独立的 ingest_xlsx.py 辅助脚本（或文档示例），只负责 把回流表抽成 txt + meta，不进验证管线。
- **行边界重建是接入环节的必需能力**（2026-09-17 补）：上游可能给「整段 dump」（记录被引号包裹、记录内换行保留、记录间无稳定分隔符）。七套业界管线都不处理这种情况（它们假设记录已成型），故本项目自建 `corpus_kit/reconstruct.py`。详见 §14。
- 文本列选择策略：有 query_text/clean_text(录音用) 优先；否则由 meta 声明；**README/read 字段保留**（倪德芝要求）。

### 2.2 记录模型（贯穿全链路）
`
Row    （行级：来自 INPUT.txt 一行）
  row_id        # 1..N，全局唯一
  fields[]      # 原字段（保留，透明透传）
  text          # 待验证文本
  gate          # {lang, charset, ...} 每项 pass/warn/fail + 原因
Sentence（句级：切句后）
  sent_id       # 全局唯一
  row_id        # 回溯原行
  text          # 单句
  tokens[] / phonemes[] / ...
`

## 3. 总体架构

形态：**一个共享核心库 + 单个可编排 skill**（一个 SKILL.md 作为 agent 入口）。skill 内部按 stage 拆分（gate → profile → report），核心库保持纯逻辑、stage 为薄壳，便于：
- /skill 注入（agent / CLI 均可用）
- 后续包一层 MCP（skill 内每个 stage = 一个 MCP tool）
- 多 agent 编排兼容（输入输出都是落盘标准中间态，不依赖对话上下文）

`
                    ┌─────────────────────────────────────┐
                    │   orchestrator /run_pipeline.py     │  （整链路一键跑，供本地/CI）
                    │   or 单个 stage CLI                  │  （可编排，供 agent 选择性调用）
                    └──────────────┬──────────────────────┘
                                   │
        ┌──────────────┬───────────┼──────────┬──────────────┐
        ▼              ▼           ▼          ▼              ▼
  stage: gate  stage: length  stage: sentence  stage: vocab  stage: phoneme(G2P)  stage: etymology(LLM)
        │              │           │          │              │              │
        └──────────────┴───────────┴──────────┴──────────────┴──────────────┘
                                   │
                    ┌──────────────▼──────────────┐
                    │      corpus_kit 核心库      │  纯逻辑、无 IO 副作用（除落盘）
                    │ config/io/segment/tokenize  │
                    │ lang/charset/g2p/stats/report│
                    └─────────────────────────────┘
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
        data/lang/*.yaml    data/ipa_dict_sw.txt   output/（报告+中间态）
`

## 4. 模块设计（逐 stage / 逐核心模块）

### 4.1 核心库 corpus_kit/
| 模块 | 职责 | 关键实现（已定稿口径） |
|---|---|---|
| config.py | 按语言加载 lang/<code>.yaml | 虚词表/NSW 正则/疑问词/字符白名单/ipa-dict 路径/G2P 兜底器；缺配置即降级 |
| io.py | 读 INPUT.txt + meta.json | UTF-8 严格校验；BOM/换行归一；记录行级 Row |
| segment.py | 切句 | 换行 + 句末 .!? + 引号闭合保护（31,561 句口径） |
| 	okenize.py | 正则分词 | 小写 + 保留 ' 与 -；另提供 whitespace 版本供单句单词数 |
| lang.py | 目标语言判定 | 虚词表命中(≥0.15) 优先 + langdetect 1.0.9（seed=0）双保险；fasttext 弃用 |
| charset.py | 字符检查/清洗 | regex \p{Block=...}；emoji 剥离不误杀正常数据 |
| reconstruct.py | 记录边界重建（§14） | 格式探测 + dump 走 CSV 引号规则 + 内容守恒断言；语言无关 |
| clean.py | 清洗：归一/质检/去重（§14） | 语言无关（`\p{L}`/`\p{Nd}`/`\X`，零词表）；hard 剔除 / soft 只记录 |
| g2p.py | G2P | ipa-dict 查表(80.8% 命中) → epitran(swa-Latn) 兜底 → ng'/dh 补丁；数字/缩写跳过 |
| phonemes.py | 音素统计 | 前鼻化合并、tʃ/ʃ/ŋ/ɲ/θ 单音素、双音素滑窗 |
| stats.py | 统计原语 | 分位数/直方图/H_norm/Gini/Top10% 词占比 |
| 
eport.py | 报告落盘 | xlsx（保留原字段+追加列+多 sheet）+ csv + 字段说明子表 + manifest.json |

### 4.2 各 stage（单 skill 内部编排，薄壳 = 入口脚本）
| Stage | 输入 → 输出 | 依赖 |
|---|---|---|
| gate_validity | INPUT.txt → records.jsonl（行级 gate 标签） | io/lang/charset |
| profile_length | records.jsonl → 长度分布 + sentences.jsonl | segment/tokenize/stats |
| profile_sentence | sentences.jsonl → 句式分布 | 标点+疑问词规则 |
| profile_vocab | sentences.jsonl → 词频/外来/实虚/NSW | tokenize/ipa-dict/虚词表/NSW 正则 |
| profile_phoneme | sentences.jsonl → 单字母/单音素/双音素 | g2p/phonemes（依赖 M4 G2P 定稿） |
| tymology_llm | sentences.jsonl → 词源分布 | 外部模型服务 endpoint + API key（配置项，key 走环境变量） |

### 4.3 G2P 执行细节（性能预算）
- 30 万词中约 80.8% 词典直取（毫秒级）；余 ~19.2% 走 epitran。
- epitran 单进程批处理，跑全量前先 100 词与 ipa-dict 抽验（一致率 <95% 停跑排查）。
- 复用 g2p_lab/venv（已含 epitran 1.24、transphone、espeak-ng 便携版）作为 G2P skill 的独立执行环境；核心库其余部分不依赖 torch，保持轻量。

### 4.4 词源大模型调用细节
- 按句分批（建议 20–50 句/批），**断点续跑**（已标句写回 jsonl）。
- 返回 JSON 容错：解析失败重试 1 次 → 仍失败该句标记 tym_fail 人工兜底；word_id 与输入词序**强校验**（长度/顺序不一致则拒绝该批结果）。
- 先 100 句人工抽检标签质量 → 全量 5038 句；按词频加权统计词源占比。

## 5. 数据流（端到端）

`
INPUT.txt + meta.json
  → [gate_validity]     行级 gate：lang/pass, charset/pass, 数值列强制数字
  → records.jsonl        （被拒行不删，标 fail 原因）
  → [profile_length]    切句 → sentences.jsonl（sent_id→row_id 追溯）
  → [profile_sentence]  句式分布
  → [profile_vocab]     词频 / 外来 / 实虚 / NSW
  → [profile_phoneme]   G2P（查表→epitran→补丁）→ 单音素/双音素
  → [etymology_llm]     词源打标（模型服务 endpoint+key，断点续跑）
  → [report]            数据集_全字段.xlsx + 维度分布 + 字段说明 + manifest.json
`

## 8. 运行流程

### 8.1 一键全链路（本地/无人值守）
`ash
python run_pipeline.py --input data.txt --lang sw --out output/
# 自动执行：gate → length → sentence → vocab → phoneme → etymology(report 阶段可选) → report
`
### 8.2 分步编排（agent / MCP 场景）
`ash
python corpus_kit/skills/gate_validity/run.py      --input input/xxx.txt
python corpus_kit/skills/profile_length/run.py     --records output/records.jsonl
python corpus_kit/skills/profile_phoneme/run.py    --python g2p_lab/venv/Scripts/python.exe
...
`
### 8.3 断点续跑
- 每个 skill 幂等：已处理 row/sent 写回中间态，重跑只补增量。
- manifest.json 记录输入哈希 + 版本 + seed，复现用 --from-manifest。

### 8.4 人工核对环节（固有流程）
1. M4：G2P 100 词抽验表（对照 ipa-dict，三方工具参照）
2. M5：词源 100 句抽检表
3. M7：整链路 100 条测试句人工核对 → 全量

- **降级不承诺指标口径等同 sw**，报告须标注「该语种口径=degraded」。

## 12. 维度框架 14 子项处置决定（2026-09-16 补，消除框架↔架构断层）

### 12.1 背景：断层从哪来

复盘发现：`docs/语料合理性验证维度框架_v1.md`（9/1，需求侧）与本文档（9/10，实现侧）**描述的不是同一批数据，且从未对齐过**：

## 14. 前置清洗模块（2026-09-17 新增）

**动机**：上游给的数据格式不可预期，且出现「整段 dump 行边界丢失」的情况——`TTS_TEXT_SWAHILI.txt`（2.5 MB）直接喂给工具集会按物理行切成 21,140 行（同一回合被切碎、`"` 单独成行 3,095 条），语言通过率被压到 79.2%，是**格式问题伪装成语料质量问题**。

**调研**：七套业界管线（C4 / Gopher / CCNet / RefinedWeb / FineWeb / Dolma / NeMo Curator）逐条判定，见 `docs/语料清洗步骤调研_v1.md`。三条关键结论：
1. 七套都**不处理行边界重建**（假设记录已成型）→ 本项目自建。
2. 业界步骤**一大半是为「文档」设计的**（词数 50–100k、min sentences ≥3、段落去重、行标点比），短句 utterance 上没有文档性，照搬会系统性删掉合法短句。
3. 语言相关步骤约占一半（语言 ID / stopword / 脏词表 / KenLM 困惑度 / ML 分类器）→ **全部不采用**。

### 14.1 分层与契约
清洗属**接入环节（§2.1 ①）**，不进验证管线；`run_pipeline.py` 与 `skills/*` **一行未改**。

```
任意格式源 → [prepare_input.py] → 清洗后 INPUT.txt + INPUT.meta.json
                                 + clean_report.json/.csv + quarantine.jsonl + clean_manifest.json
                                 → [run_pipeline.py 原样] → 报告
```

### 14.2 语言无关性（硬约束）
- 源码**不得出现 Latin-only 字符类**（`[A-Za-z]`/`a-z`/`A-Z`），一律走 Unicode 属性 `\p{L}` `\p{Nd}` `\p{Alpha}` `\p{P}` `\p{M}` `\p{Cc}` `\p{Cf}`。
- 长度按**字素簇 `\X`** 计，不按码点。
- **零词表**：不放任何语言 stopword / 白名单 / 脏词表。
- 由 `tests/test_corpus_clean.py::TestLanguageAgnostic` **守卫**（含注入回归验证，确认该守卫真能失败）。

### 14.3 步骤
① 重建（格式探测 / dump 走 CSV 引号规则 / tsv·csv 取列 / txt 逐行 + **内容守恒断言**）
② 归一（去包裹引号 → 换行→空格 → 剥 `Cc`/`Cf` → 剥噪声 → NFC → 折重复 → 空白归一）
③ 质检（hard：empty/no_letters/no_words → 剔除；soft：占比类 → 只记录）
④ 去重（去重键归一 → 精确哈希 →[可选] MinHash/LSH）
⑤ 落地（INPUT.txt + 四份审计产物）

### 14.4 两处有意偏离业界（须留档）
1. **非字母数字比的分母排除空白**：业界该统计针对内容字符；计入空格会让正常带标点短句全部越界（实测把 Swahili 误杀 82 → 13 条）。
2. **soft/hard 两档**：占比阈值是为文档定的，短句上天然偏高（`Sawa..`/`Mungu..` 是合法斯语）→ 只记录不剔除。「不轻删」原则的落点。

### 14.5 实测（TTS_TEXT_SWAHILI.txt）
物理行 21,140 → 逻辑记录 **5,038**；**内容签名守恒**（源与重建签名逐字符相等，2,459,928 字符，`dropped_chars=0`）；与 canonical 逐字相同 **5,037/5,038**（1 条 dump 侧吞了首词引号）；保留子集**字母数 1,938,786 → 1,938,786 零丢失**；硬剔除 0；去重 596；soft flag 13（保留）。下游：**4,442 行 / 25,680 句 / 语言通过 95.09% / 字符通过 99.77%**。

**口径变化提示**：`newline_to_space=true` 合并记录内换行（utterance 应单行），句数 31,561 → 25,680（「短语」1,922 → 12）。要保原句数口径则设该开关为 `false`。

### 14.6 边界（不在本次范围）

## 15. 多语种通用化（2026-09-18 新增）

**目标口径（用户原话）**：「不管我扔给它什么语种的 txt 文件，它都能按照我的要求帮我处理；处理不了，
或者我的要求有误、满足不了实际情况，那就诚实地告诉我。」三条硬要求：
① 进来什么处理什么（任意 txt 可进，不做隐式合并）；② 能力边界如实报（报告带「能力与口径」块）；
③ 指令冲突要顶嘴（`--lang` 与数据不符必须标出，不按错的指令静默跑完）。

### 15.1 架构：检测层 + 脚本家族 + 语言薄层

```
任意 txt → 检测层 → 脚本家族层 → 语言薄层 → 管线 → 报告（含能力与口径块）
           编码/格式(已有)  9族·语言无关规则  18语·语言特有资源
           脚本探测/语言探测/指令校验
```

- **`data/script/<family>.yaml`**（9 族：latin/arabic/devanagari/bengali/gujarati/tamil/cyrillic/han/generic）：
  token 正则、核心字符、越界块（**结构性推导**：`ALL_SCRIPT_BLOCKS − 本族块`，杜绝「目标语被当外语」）、
  句末标点（含 `।॥؟۔`）、引号对、G2P 词形判据、必须保留的格式符（ZWNJ/ZWJ）、音节元音集。
- **`data/lang/<code>.yaml`**（18 语）：虚词表、疑问词、NSW 正则、词典路径、epitran 码、音节口径、词源候选。
- **新语言 = 零代码**：家族已有 → 只加语言 yaml；新文字体系 → 加一个家族 yaml。
- **检测层**（`corpus_kit/detect.py`）：`\p{scx}` 脚本采样 + langdetect + `--lang auto` +
