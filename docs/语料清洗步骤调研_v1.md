# 语料清洗步骤调研 v1

> 日期：2026-09-17 ｜ 项目：TTS 回流语料验证工具集 · 前置清洗模块
> 目的：为「前置清洗」定步骤与阈值。要求两条硬约束：**按业界标准做**、**必须语言无关**（不限本次 sw）
> 方法：读七套主流语料清洗管线的一手资料（论文/参考实现），逐条判定是否适用、是否语言相关
> 结论落点：`data/clean.yaml`（阈值）+ `corpus_kit/{reconstruct,clean}.py`（实现）

---

## 0. 结论速览

1. **行边界重建是业界没有、但本项目必需的一步**。七套管线都假设「记录已经是记录」（从 WARC/文件/JSONL 读入），没有任何一套处理「整段 dump 行边界丢失」——而这正是 `TTS_TEXT_SWAHILI.txt` 的问题。本模块自建（`reconstruct.py`），口径为 CSV 引号规则。
2. **业界步骤一大半是为「文档」设计的，短句 utterance 上会退化或过删**。word count 50–100,000、min sentences ≥3、段落级去重、行标点比……测的都是「文档性」，5–15 词的短句没有文档性。**照搬会系统性删掉合法短句**（FineWeb 自己都因过删 −30% token 弃用了句末标点过滤）。
3. **语言相关的步骤约占一半**（语言 ID、stopword、脏词表、KenLM 困惑度、ML 质量分类器）。本模块**全部不采用**，只保留语言无关的 Unicode/统计口径。
4. **实测验证**（`TTS_TEXT_SWAHILI.txt`）：重建 5,038 条（**内容签名守恒**——源与重建的签名逐字符相等，2,459,928 字符，`dropped_chars=0`）；保留子集**字母数 1,938,786 → 1,938,786，零丢失**；去重 596 条；硬剔除 0 条。

## 1. 七套管线的有序步骤与关键阈值

### C4 / T5（Raffel et al. 2020, JMLR 21(140)）
非英语过滤（langdetect ≥0.99）→ 行级过滤（词长 >1000 丢、去引用标记、要求句末标点、每行 ≥5 词）→ 页级（≥3 句、无花括号）→ 脏词表（LDNOOBW）→ 三句跨度去重。
阈值：`MIN_WORDS_PER_LINE=5`、`MIN_NUM_SENTENCES=3`、`MAX_WORD_LENGTH=1000`。

### Gopher / MassiveText（Rae et al. 2021, arXiv:2112.11446）
英语过滤 → SafeSearch → 质量启发式 → 重复过滤 → 文档级 MinHash 去重 → 测试集污染去除。
质量阈值（原文）：词数 50–100,000；平均词长 3–10；`#` 或 `…` 的符号/词比 ≤0.1；以项目符号开头的行 ≤90%；以省略号结尾的行 ≤30%；≥80% 的词含字母；≥2 个英语 stopword。
重复阈值（Table A1）：重复行比 0.30；重复段落比 0.30；重复行字符比 0.20；top-2/3/4-gram 字符比 0.20/0.18/0.16；重复 5–10-gram 字符比 0.15→0.10。
去重：精确 + MinHash 13-gram Jaccard > 0.8。

### CCNet（Wenzek et al. 2020, arXiv:1911.00359）
段落 SHA1 去重 → 语言 ID（176 语 fastText）→ KenLM 5-gram 困惑度分桶（head/middle/tail，`percentile_head=30, percentile_tail=60`）。
归一（`text_normalizer.py`）：NFD 去变音符、去 C0+C1 控制字符、73 条多语标点映射、数字→0。**无阈值启发式**，质量靠困惑度分桶。

### RefinedWeb / MacroDataRefinery（Penedo et al. 2023, arXiv:2306.01116）
URL 过滤 → trafilatura 抽取 → fastText 语言 ID **≥0.65** → Gopher 质量启发式 → 行级修正 → MinHash → 精确子串去重。
行级修正：全大写行丢、纯数字行丢、计数行丢（如 `3 likes`）、单词行丢、短行（≤10 词）匹配样板模式则改；**被标记行的词 > 文档总词 5% 则丢整个文档**。
MinHash：9000 哈希 / 5-gram / 20 桶 × 450。
**原文警告**：「这些过滤器必须逐语言调整，直接从英语搬到其他语言会**过度过滤**」。语言 ID ≥0.65。

### FineWeb（Penedo et al. 2024, arXiv:2406.17557）
URL 过滤 → trafilatura → fastText **≥0.65** → Gopher 重复 + 质量 → C4（**去掉句末标点规则**）→ FineWeb 质量 → MinHash。
FineWeb 自有阈值：行末标点比 ≤0.12；短行比（≤30 字符）≥0.67；重复行字符比 ≥0.10。
MinHash：5-gram / 14 桶 × 8 哈希（≈0.72 相似度）。
**关键**：句末标点过滤因「删掉过多数据（−30% token）」被弃用。

### Dolma（Soldaini et al. 2024, arXiv:2402.00159）
taggers + mixers 框架。取 **Gopher All** + 单条 C4 规则（段末标点，`MIN_WORDS_PER_LINE=3`）。
**明确否决 CCNet 困惑度分桶**。
自有规则：删除重复序列 **> 100 UTF-8 字符**。
去重：URL + 文档 + 段落级，Bloom 过滤器（精确，无 MinHash）。

### NeMo Curator（NVIDIA，多语种导向）
语言管理 → 内容清洗（`UnicodeReformatter`(ftfy) / `NewlineNormalizer` / `UrlRemover`）→ 去重（精确/模糊/语义）→ 质量过滤（30+ 启发式）→ 专业化 → 交织。
启发式默认：词数 50–100,000；平均词长 3–10；最大词长 1000；重复行比 0.7；重复段落比 0.7；非字母数字比 **0.25**；符号/词比 0.1；数字/文本比 0.15；URL/文本比 0.2；空白比 0.25；英语常用词 ≥2；**含字母词比 0.8**；项目符号行比 0.9；括号比 0.1；省略号行比 0.3。
去重：精确 MD5 / 模糊 MinHash+LSH（`char_ngrams=24, num_bands=20, minhashes_per_band=13`）/ 语义。
**多语种**：176 语 FastText；stopword 模块按语言；中日泰等无空格语言特殊处理。

## 3. DROP 清单：业界有、但短句语料不适用

| 步骤 | 丢弃理由 | 出处 |
|---|---|---|
| word count 50–100,000 | 下限 50 会删掉几乎每条 utterance | Gopher / NeMo |
| min sentences ≥3、min words/line ≥3–5 | utterance 常是单句或片段（本语料「短语」占有量） | C4 / Dolma |
| 句末标点过滤 | FineWeb 已因过删（−30% token）弃用；对话文本常无句末标点 | C4 → FineWeb 弃用 |
| 段落/句子跨度去重 | utterance 内无段落；改为 utterance 级去重 | C4（三句跨度）/ Dolma（段落） |
| >90% 行以项目符号开头 / >30% 行以省略号结尾 | 多行文档统计，短句下退化 | Gopher |
| 短行比 ≥0.67 / 行标点比 ≤0.12 | 同上是多行文档统计 | FineWeb |
| 平均词长 3–10 | utterance 里短词（`na`/`wa`/`ya`）占比高，易误杀 | Gopher / NeMo |
| 全大写行 / 纯数字行丢弃 | TTS 语料里 `TECNO CAMON`、编号是合法内容 | RefinedWeb 行级修正 |

## 4. 本模块采用的步骤（语言无关 + 短句适配）

```
① 接入 reconstruct.py
   R1 UTF-8 严格解码 + BOM 剥离 [+ 可选 chardet/ftfy mojibake 修复]
   R2 格式探测 auto|dump|txt|tsv|csv（xlsx 请先走 ingest_xlsx.py，本脚本不吃二进制）
   R3 记录边界重建（dump 走 CSV 引号规则；tsv/csv 按列；txt 逐行）
   R4 内容守恒断言（源 vs 重建签名须相等，否则报错——不靠猜）
② 归一 clean.normalize
   N1 去包裹引号 + 双写引号还原    N2 换行→空格（须在剥控制字符之前）
   N3 剥 \p{Cc}\p{Cf}（零宽/BOM/软连字符）  N4 剥噪声（复用 charset.NOISE_RE）
   N5 NFC                          N6 重复长串折叠（默认 100）
   N7 空白归一
③ 质检 clean.quality（flags，不轻删）
   hard：empty / no_letters / no_words         → 剔除
   soft：nonalnum_ratio / symbol_word_ratio / words_with_alpha / too_short → 只记录
④ 去重 clean.dedup
   D1 去重键归一（casefold → \p{Nd}→0 → 去 \p{P} → 折叠空白）
   D2 精确哈希（sha256 前 16）    D3[可选] MinHash/LSH
⑤ 落地 scripts/prepare_input.py
   W1 INPUT.txt + INPUT.meta.json（契约同 ingest_xlsx）
   W2 clean_report.json/.csv（逐条 flag + 阈值 + 计数 + 输入 sha256）
   W3 quarantine.jsonl（剔除项 + 原因 + 原文，可回滚）
   W4 clean_manifest.json（入参/阈值/版本/seed → 可复现）
```

### 4.1 与业界的两处有意偏离（必须说明）

1. **非字母数字比的分母排除空白**。业界（NeMo）该统计本针对内容字符；若把空格计入分母，短句里空格占比高，会让「正常带标点的句子」全部越界——实测此偏离把 Swahili 误杀从 82 条降到 13 条（且那 13 条只是标点密度高，已降为 soft 不剔除）。
2. **soft / hard 两档**。业界这些占比阈值是为文档定的，短句上天然偏高（实测 `Sawa..`、`Mungu..` 是合法斯语）。故占比类只记录不剔除，只有「结构上不成立」（无字母、无词、空）才剔除。这是「不轻删」原则的落点。

## 5. 实测结果（TTS_TEXT_SWAHILI.txt，2.5 MB）

| 指标 | 值 |
|---|---|
| 物理行 → 逻辑记录 | 21,140 → **5,038** |
| 内容守恒（源 vs 重建签名逐字符比对，空白只折形态不失内容） | **相等**（2,459,928 字符，`dropped_chars=0`） |
| 与 canonical 逐字相同 | 5,037 / 5,038（1 条因 dump 侧吞了首词引号，仅差 1 字符） |
| 全部记录字母数（重建后） | 1,990,891 |
| 保留子集字母数（清洗输入 = 清洗输出） | **1,938,786 = 1,938,786（零丢失）** |
| 硬剔除 | 0 |
| 去重剔除 | 596（均为精确重复，逐条可追溯 keeper） |
| soft flag | 13（只记录，保留） |

下游效果（清洗后跑 `run_pipeline --skip-etymology`）：行数 **4,442**，句数 25,680，语言通过率 **95.09%**，字符通过率 **99.77%**，G2P 抽验折合一致率 0.975（pass）。

**一处需知的口径变化**：`newline_to_space=true` 会把记录内部换行合并（TTS utterance 应是单行），故句数由未清洗的 31,561 变为 25,680，「短语」由 1,922 降至 12。这是**有意的**；若要保留原句数口径，把 `data/clean.yaml` 的 `normalize.newline_to_space` 设为 `false` 即可。
