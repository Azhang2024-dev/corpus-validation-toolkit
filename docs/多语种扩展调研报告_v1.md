## 0. 结论速览（TL;DR）

1. **现状不是「只有 sw 数据」，而是「骨架参数化了、但资源与降级逻辑都没落地」**。`Config` 已按 `data/lang/<code>.yaml` 加载、`--lang` 已串通 6 个 stage；但缺 yaml 时**静默回落到 sw 的 `ipa/sw.txt` 与 `epitran swa-Latn`**，会产出以斯语口径算出的错误指标（本地实测确认）。
2. **对重点 4 语种，资源成熟度是「fr 最好、ur/bn 可用但薄」**：
   - **fr**：可用 **Lexique383**（14 万词，含音素+**音节数**+词元，CC BY-SA 4.0）——能做到与 sw 同等成熟度；
   - **ur**：**ipa-dict 无、WikiPron 仅 7.7k**，且**正字法系统性省略短元音 → 音节数在字符层面根本算不出**（最硬的一处）；
   - **bn**：**ipa-dict 无、WikiPron 7.3k**，合体字使**字符数必须按字素簇计**，词元基建最弱（spaCy/Stanza 均无、UD 仅 56 句）。
3. **两处旧调研结论已过时，本次本地实测更正**：epitran **已支持 `urd-Arab` 与 `ben-Beng`**（旧文档记「urd 未见」）；ipa-dict **确实没有 ur/bn**（此项旧结论正确）。
4. **三个「致命」实现缺陷会让任何非拉丁目标语直接失效**（本地实测）：`TOKEN_RE=[A-Za-z'\-]+` 使 ur/bn 文本 token 数=0 → 语言判定 `fail/no_tokens`；`CORE_RE` 只认拉丁+数字 → 非拉丁目标语恒触发 `mostly_noise`；`DEFAULT_FOREIGN_BLOCKS` 把 Arabic/Devanagari/Bengali/Ethiopic 当「外语」→ 对 ur/bn/hi/ha 目标语**必然误杀**。
5. **跨语种不可直接比口径**：业界自己就分两套（Azure 官方：拉丁 5–30 词/句 vs **非拉丁 4–80 词/句**）；「覆盖率 %」的分母（音素表大小）与统计单位（码点/字素簇）都不同，跨语种裸比会失真。
6. **最大工程风险是文本归一化（TN）**：fr 支持完善（num2words + NeMo-TN 都含 fr）；bn 只有数字可解（num2words 有 `bn`）；**ur 最差（num2words/indic-num2words/NeMo 均无 ur，且东阿拉伯数字 ۰-۹ U+06F0–06F9 与西阿拉伯数字混用）**。

## 3. 调研发现

### 3.1 G2P 与发音词典（逐语种）

### 3.2 语言识别（LID）与脚本消歧

- **现有 `langdetect 1.0.9` 的短板有论文佐证**：DIVERS-Bench 全量宏 F1 仅 **41.9**，但**限定到其支持语后跳到 91.3** → 主要败在覆盖面，而非纯短文本能力。且官方明示**非确定性**（`seed=0` 只是掩盖症状）。
- **覆盖缺口（对本题全集）**：langdetect 缺 **ha**、**fil**（"tl" 为准）；fastText `lid.176` 亦无 ha；lingua-py（75 语）无 ha；AfroLID（517 非洲语）不覆盖 ur/bn/fr。
- **code-switch 是公共短板**：DIVERS-Bench 实测 code-switch **full-match F1 几乎趋近 0**（最好 OpenLID eu-es 仅 16.02）。**句级 `detect()` 不能判混合比例**，必须走「句级主语言 + 词级虚词/脚本切分」。
- **推荐两段式：脚本检测 → 脚本内消歧**。lingua 与 GlotLID 官方都这么做（GlotLID 官方 FAQ 推荐配 GlotScript）。**限定候选语集**可显著提精度（DIVERS-Bench：窄模型 F1 41.9→91.3）。对本项目的直接价值：**hi vs ur 文字不同，脚本即可几乎无损区分**；真正要在拉丁脚本内消歧的是 **id/ms、es/pt/fr、sw/ha**。
- **π 对非拉丁目标语**：`langdetect_code: ha` 永远匹配不上（langdetect 无 ha 标签）；现有 `check_lang` 是 `fw_score>=阈值 OR langdetect命中` 的**选言**语义过松，短句易假通过。

### 3.3 字符 / 非拉丁文字处理（本地实测 + UAX 一手）

| 现象 | 实测证据 | 正确做法 |
|---|---|---|
| **Block ≠ Script** | `\p{Block=Arabic}` **不含** Presentation Forms-A/B（FB50–FDFF, FE70–FEFF，797 码位） | 用 **`\p{scx=...}`（Script_Extensions）** |
| **Script=Arabic 漏字符** | `\p{Script=Arabic}` 对 harakat（U+064B）、tatweel（U+0640）、阿拉伯逗号（U+060C）**返回 False**（它们 Script=Inherited/Common） | `\p{scx=Arab}` 全部覆盖（实测 True） |
| **婆罗米系不能按码点计数** | `ক্ষ`=3 码点/1 字素簇；`কি`=2/1；`र्‍य`=4/1（UAX #29 GB9c：virama 连接的合体字不断簇） | Python `regex` 的 `\X` 或 PyICU BreakIterator |
| **ZWNJ/ZWJ 是正字法符** | U+200C 在 Bangla 是有意义的（virama 与辅音之间）；当前 `NOISE_RE` 把它当噪声剥离 | 移出噪声集；用脚本白名单时额外显式允许（ZWJ/ZWNJ 的 scx 不含 Bengali） |
| **RTL 归一化** | 对阿拉伯文本误用 NFKC/NFKD 会折叠位置变体、破坏往返（UAX #15） | **统一 NFC**，阿拉伯文本严禁 NFKC |

> **设计建议**：字符检查从「外语黑名单」改为「**目标语合法集白名单**」= `\p{scx=<目标脚本>}` ∪ 语种附加符 ∪ 显式 Common/Inherited（ZWJ/ZWNJ/virama/bidi）∪ 空白与通用标点。

### 3.4 音节 / 长度口径

| 语种 | 难度 | 依据与可行方案 |
|---|---|---|
| **sw** | 易 | 元音=音节核（现状最稳，作规则正确性基准） |
| **fr** | 难（资源最好） | 静音字母/鼻化元音/**liaison**使同一词在不同语境音节数不同 → **直接查 Lexique383 的 `nbsyll`**，并声明「不计连读」口径；pyphen 的连字点 ≠ 音节 |
| **ur** | **极难（最硬）** | **正字法系统性省略短元音（harakat）→ 字符层根本无法推音节**；须「归一 → 发音词典/G2P → 数元音核」（PronouncUR 64% 准确率；478k 非商用词典）。**建议 ur 长度口径放弃音节，改「词数+音素数+字符数」** |
| **bn** | 难 | 合体字+固有元音 → 需 aksara 级解析；**字符数必须按字素簇**；无成熟音节库（IndicNLP 有 `syllable/` 模块，待实测） |
| 其余 | 中/易 | 天城文系（hi/mr/gu）同 bn 但合体更简单；es/pt/id/tr/fil/ha 近音位拼写可靠；zh 字=音节；ar 同 ur 类 |

### 3.5 词汇 / 外来词 / NSW

- **停用词/功能词**：fr/hi/ar 有现成（NLTK+stopwords-iso）；**ur 无 NLTK 版**（stopwords-iso 有）；**bn 两处都有**。**UD 闭类词性抽取**（`ADP/AUX/CCONJ/DET/NUM/PART/PRON/SCONJ`）是 ur/bn 自建虚词表最可行的路径（现有工具的虚词表恰恰是 gate 的第一道依据）。
- **词频**：wordfreq 支持 fr(7源+large)、bn(5源+large)、**ur 仅 3 源且无 large**。
- **外来词判定**：**fr/ur/bn 三语均无现成开源资源**（fr 无 anglicism 词典；ur 阿拉伯/波斯/英语借词无形态标记；bn 的 tôtsômo/tôdbhôbo 分层无自动工具）。建议本期降级为「**疑似外来词启发式扫描**」，不做精确判定。
- **NSW 与非拉丁数字**：ur 东阿拉伯数字 **۰-۹ = U+06F0–U+06F9**；bn 孟加拉数字 **০-৯ = U+09E6–U+09EF**；fr 书写数字+缩写。注意：回流语料常混用两套数字系统，需建「数字/标点等价类」映射。

### 3.6 语料质量方法学与业界阈值

| 维度 | 业界阈值（一手） | 来源 |
|---|---|---|
| 最少话语数 | **300** 条起步；特殊人格 1000–2000 | Azure 官方 |
| 单句时长 | **2–15 s**（上限 20 s；>30 s 直接拒） | Azure / Riva 10–20 s |
| **单句词数** | **拉丁 5–30 / 非拉丁 4–80**（同一文档两套阈值） | Azure 官方 |
| 句式配比 | 陈述 70–80% / 短句 ~10% / 疑问 10–20% / 感叹 10–20% | Azure |
| 音素覆盖 | 英语 44 音素全覆盖 + **相对基线的正确分布**（≠覆盖率%） | Riva；英语基线用 Harvard Sentences |
| 弱音素专项 | **最稀有 20 音素，每音素 ≥50 句** | IndicTTS（AI4Bharat） |
| 分布均衡度 | **PCD = coverage×(1−JSD)**；或余弦相似度（抗规模差异） | corpusgen；BASPRO 0.96 |
| 词汇多样性 | TTR 受长度影响严重 → 建议 **MTLD 或按长度分桶** | 多篇 |
| 质量闸门（可扩展多语） | **样本 CER >10% 剔除、录音 CER >5% 剔除** | Meta MMS（唯一验证过 1100+ 语的做法）|
| 禁止项 | 重复句、相似模式（easy/easier） | Azure |

> **重要校准**：arXiv 2309.08127 明确把「phoneme-balanced selection」当作**被超越的基线** → 音素覆盖是**必要非充分**条件，不能把「音素覆盖率高」等同于「数据集质量高」。JSD 各变体对**语料规模不平衡**敏感（LREC 2020），跨语种比较优先用余弦相似度或 PCD。

### 3.7 跨语种可比性（本项目最易踩的坑）

| # | 坑 | 机制 |
|---|---|---|
| 1 | 切句规则不可移植 | fr 缩写 `M./Dr.`；ur 的 `۔`(U+06D4)/`؟`(U+061F)；bn 的 `।`(U+0964)/`॥`(U+0965) |
| 2 | 码点 vs 字素簇 | bn/ur 按 `len(str)` 会**系统性高估 2×+** |
| 3 | 字符数不是可比长度 | BPC ↔ 字符数 ρ=−0.81；BPB ↔ 字节数 ρ=−0.94（arXiv 2608.25089 一手） |
| 4 | 音节定义各异 | fr≈37 音素 / bn≈29 辅音+7 元音 / ur≈48 音素 → **覆盖率分母不同** |
| 5 | 同文字近语言难分 | id/ms、es/pt 在拉丁脚本内；hi/ur 因文字不同反而易分 |
| 6 | 长度门槛应分语种 | Azure 官方即分拉丁/非拉丁两套 |
| 7 | 参考基线不可跨语种复用 | Riva 用 Harvard Sentences 作英语基线，ur/bn **无等价物** |

> 业界解决「跨语种可比性」的主流做法是**控制文本内容（平行翻译句）**（FLEURS 用 FLoRes-101 的 3001 句译成 101 语）；**回流语料不是平行文本，用不了这招**，因此必须**显式记录并公开度量口径**。

## 4. 重点 4 语种逐语种可行性小结

### sw 斯瓦希里语 — 现有方案最稳，作「基准语种」
G2P：epitran `swa-Latn` ✓ / ipa-dict `sw.txt` 48,308 条 ✓ / gruut ✓。音节：元音=音节核 ✓。短板：WikiPron 仅 370 条（扩词表无余量）。**定位：保持现状，作其他语种的规则正确性与口径校准基准。**

### fr 法语 — 综合资源最优，可做到与 sw 同等成熟度
- G2P：epitran `fra-Latn`（⚠官方标歧义）/ gruut / DeepPhonemizer `latin_ipa_forward` / espeak 多路可选。
- 词典（**决定性优势**）：**Lexique383**（CC BY-SA 4.0，14 万词，`phon`+`nbsyll`+`lemme`+`cgram`）→ 音素、音节、词元一次到位；ipa-dict `fr_FR` 兜底。
- 虚词表：NLTK `french` / stopwords-iso ✓。
- 文字：拉丁+变音符+撇号 → 注意 **NFC 归一**与省音分词（`l'homme`）。
- TN：num2words `fr*` + NeMo-TN 均含 fr ✓（4 语种中风险最低）。
- **唯一硬伤**：liaison 跨词，逐词 G2P 必然漏；需声明「不计连读」口径。
- 实测旁证（现有测试集报告）：fr TTR 15.2%、跨文件 3 个 ×500 句**完全同源**（`fr_cv3_Jean/Nico/zero_shot`）→ 去重是本语种的头号问题。

### ur 乌尔都语 — 工具「有」，质量与数据「薄」
- G2P：**epitran `urd-Arab` ✓（首选，MIT）** / espeak `ur`（GPL）/ transphone；charsiu `urd.tsv` 不作生产。
- 词典：**ipa-dict ✗；WikiPron 仅 7,709** → 无权威开源 IPA 词典，验证集上限受限。
- 虚词表：stopwords-iso ✓，NLTK ✗ → 建议从 `UD_Urdu-UDTB`（5130 句，**CC BY-NC-SA**）按闭类词性抽取。
- **音节：极难** → 正字法省略短元音（`Diacritics in Urdu are normally not written`）→ **建议放弃音节口径**。
- 文字：RTL + Nastaliq + abjad + 二合字母 ھ + **ZWJ/ZWNJ** → 分词/长度/字素簇须专门化。
- TN：**4 语种中最差** —— num2words **无 ur**、indic-num2words 把 ur 列「planned」、NeMo/WeTextProcessing 均无 ur；且 ۰-۹ 与西阿拉伯数字混用。**自研量最大。**
- 实测旁证：ur TTR 10.1%；`ur_kathbath_test.lst` 内部 **1859/1959 条完全重复**（同文多音频复刻）→ 现有文档已标。

### bn 孟加拉语 — 工具多、权威数据少、NLP 基建最弱
- G2P：epitran `ben-Beng` ✓ / espeak `bn` / transphone `ben` ✓；专用规则法自报准确率仅 73% ⚠。
- 词典：**ipa-dict ✗；WikiPron 7.3k**；bangla-g2p 词表**无许可** 。
- 虚词表：NLTK `bengali` ✓ + stopwords-iso ✓（少数两处都覆盖的语种）。
- **字符计数必须按字素簇**（合体字 + 固有元音 + ZWJ）；音节无成熟库。
- 词元基建最弱：**spaCy ✗、Stanza ✗、UD `bn_bru` 仅 56 句**。
- TN：**数字可解**（num2words 有 `bn`、indic-num2words 有 bn），但日期/货币/缩写无现成方案。**Google 明确 bn-IN 不支持自定义发音**（发音控制受限）。
- 实测旁证：bn TTR 仅 1.3%（受 kathbath 复刻型文件拖低）；`bn_kathbath_test.lst` 内部 **2136/2236 完全重复**。

## 6. 关键风险与坑（按优先级）

1. **许可（最高优先级）**：现有链路是 ipa-dict(MIT)+epitran(MIT)；引入 **espeak-ng/phonemizer 会带来 GPL-3.0 传染**（OpenPhonemizer 的存在动机即为此，其 README 明说要替代「non-GPL software 里的 espeak」）。Lexique383=CC BY-SA 4.0（需署名+相同方式共享）；URDUTTS=CC BY-NC（不可商用）；stopwords-iso **未声明许可**；bangla-g2p **无许可**。**逐语种许可需单独维护清单**。
2. **ipa-dict 对 ur/bn 完全缺失** → 现有「查表+兜底」架构在 ur/bn 退化为纯 G2P，失去词典校验锚点。
3. **TN 是扩展的最大工程风险**：fr 完善、bn 仅数字可解、**ur 几乎全缺**。
4. **音节口径在 ur 上不可行、在 fr/bn 上需专门方案**。
5. **跨语种裸比指标失真**（覆盖率分母、统计单位、参考基线均不同）。
6. **非拉丁目标语的三个致命实现缺陷**（见 §2.3），不改则 ur/bn 无法接入。
7. **词元/形态基建不对称**：fr 成熟；ur 尚可（Stanza+UD+urduhack）；**bn 最弱**（无 spaCy/Stanza，UD 56 句）。
8. **code-switch 判不了**（句级 LID full-match F1≈0）。
9. **现有测试集本身的质量问题**（同源/复刻重复）：fr 3×500 完全同源；ur/bn 的 kathbath 文件内 95% 完全重复 → 分布报告需先做去重/同源标注。

## 7. 建议的扩展路线（分阶段）

**阶段 0（先修地基，不改选型）**
1. `config.py`：yaml 缺失时**显式抛错或标记 `degraded=True`**，禁止静默回落 `ipa/sw.txt` / `swa-Latn`；`resources_ok` 按目标语校验。
2. `tokenize.py` / `charset.py` / `phonemes.py`：字符串类改**按目标脚本白名单**（`\p{scx=...}`），token 正则覆盖目标脚本，`NOISE_RE` 移出 ZWNJ/ZWJ。
3. 长度统计：字符数改 **字素簇**（`regex` 的 `\X`）。
4. 落地 `degraded` 上报（报告 sheet + manifest）。

**阶段 1（重点 4 语种打通）**
5. 新增 `data/lang/fr.yaml`、`ur.yaml`、`bn.yaml`：虚词表（fr 用 NLTK/iso；ur/bn 用 UD 闭类抽取）、NSW 正则（含 ۰-۹ / ০-৯）、疑问词、脚本白名单、G2P 配置。
6. 词典：fr 挂 Lexique383、ur/bn 挂 WikiPron（含许可标注）。
7. 切句：支持 `۔ ؟ ۔ । ॥` 与 fr 缩写保护表。
8. 音素切分：按语种配置音素拆分规则（替换 sw 专属的前鼻化/tʃ 规则）。
9. 词源 prompt 按语种参数化（候选词源清单入 yaml）。

**阶段 2（口径与质量方法学升级）**
10. 长度门槛按**文字体系分档**（拉丁/非拉丁两套，引用 Azure 官方依据），并同时报「词数 + 音素数」两口径。
11. LID 引入**脚本检测 → 限定候选集**两段式，并考虑 lingua/GlotLID 作短文本主力（ha 单独兜底）。
12. 分布均衡度指标：跨语种优先用**余弦相似度 / PCD**，弱音素按 IndicTTS 口径（最稀有 20 音素 ≥50 句）。
13. 引入 **CER 双阈值**（样本 10% / 录音 5%）作为可扩展质量闸门。

**阶段 3（其余历史测试集语种）**
14. 按同构模板批量加 yaml（hi/mr/gu/ta/te 走婆罗米系字素簇；ar/ru 等按各自脚本），逐语种抽验后再承诺口径。
